# RAG-v1 冻结评估集

本轮目标是形成真实基线，不优化生产检索、分类或生成。M2 两份冻结查询/报告、16 条合成案例、M3 原有法条清单和 `v0.1.0-m3` 标签均不修改。

## 数据和标注

- 检索查询 160 条：案例 80、法条 80；每路每领域 20 条，其中开发集 15、保留测试集 5。合计 120/40。
- 案例正例 64、负例 16，包含口语改写、噪声、四题多案例需求及未覆盖场景；案例都是演示合成数据。
- 法条正例 56、负例 24，包含多依据、8 条缺日期题、4 条旧年份未覆盖题、8 条知识缺口题和4条超范围题。仅比较固定197条语料，不假设库外不存在相关法律。
- 从法条查询选40个端到端场景，每领域10个，其中12个多轮场景；共56轮请求。场景来自开发集36题、保留集4题，不应把40题全称为盲测。
- 每个标注记录资料 ID、1/2/3 级相关程度、理由、问题范围、日期区间和预期行为。3为直接规则，2为补充前提，1为辅助一般依据，未列出的资料按0处理。
- `expected_behavior` 区分 answer、clarify、insufficient；多轮场景另外指定 conflict/cancelled 和字段保留要求。

标注由开发代理基于原文完成，为 `agent_draft_pending_expert`，没有外部专家审核；“全部相关依据”仅指固定语料内、问题明确限定争点下的标注目标，不是对现实法律资料的穷尽证明。逐题复核已发现部分补充依据和追问预期值得重新审查，见验收记录；本版不据观察到的排名改标签。

按议题组划分开发和保留集；同一案例主题的改写不跨组（每领域第四案例主题在保留集）。编写者知道M2原有主题，且同一开发代理编写语料关键词和查询，因此只是议题划分的内部评估，不能称为独立第三方盲测。首轮全部运行后，保留集已经被观察；后续不得用它调优后仍宣称第一次独立验收，应另建未见测试集。

## 冻结与运行

`manifest.json` 在首次检索和模型运行前生成，保存查询、场景、全部语料及快照 SHA-256。运行器验证哈希、分组、ID、金标准来源和规模；失配即拒绝运行。修正标注必须另建版本，并保留原报告，不能原地变更以提高分数。

指标按案例向量、案例BM25、案例融合、法条BM25分开汇总，并按开发/保留、领域、类别细分：

- Hit@1/3/5：Top-K至少一个相关项。
- Recall@1/3/5：Top-K相关项数 / 固定语料中已标注相关项总数。
- Precision@1/3/5：Top-K相关项数 / K；不足K条不补分，负例也进入此指标分母。
- MRR@1/3/5：首个相关项排名倒数的均值，截断到K；不是完整列表的MRR。
- NDCG@1/3/5：增益 `2^grade-1`，折损 `log2(rank+1)`；同时输出理论 Recall@K 上限。
- 空标签题的 Hit/Recall/MRR/NDCG 为空并排除分母，单独计算误召回率；不会把返回空列表算作100%召回。
- 法条版本匹配率只检验固定元数据是否覆盖给定日期区间，不代表实际法律适用正确。法条检索评估直接提供标注领域；领域识别错误在端到端评估发现。
- 服务错误单独计数；正常查询指标排除错误但保留精确分母，另报包含故障的有效命中率。下游生成失败不会抹除已观测到的候选/筛选阶段结果。
- P50/P95 采用线性插值，计时不含建索引和加载权重；单机顺序运行，不是负载测试。

端到端报告保存合成输入、各模型节点输入/输出、响应及错误，不保存授权Token或配置密钥。真实HTTP历史用于核验字段来源；Redis只清理本轮合成账号的精确键前缀。行为识别是可审计的程序规则，不能替代语义审核。

运行命令和结果见 [RAG-v1验收](../../../../docs/acceptance/rag-v1.md)。
