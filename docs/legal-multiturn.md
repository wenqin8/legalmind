# 官方法条与多轮任务扩展

2026-09-18 用户批准：问答补事实和文书补字段同时实施，覆盖现有四领域，采用官方核验后的本地法条版本和人工更新。此扩展取代 M3 初始范围中“不新增真实法条、不做自然语言逐轮提取”的限制，不修改 M2 冻结案例、查询、相关性标签及索引参数。

## 问答

每轮先从当前用户消息提取事实，保留原句和来源 `source_turn_id`。事件日期、关系建立日期、知悉侵害日期、结束日期分别记录，不能把咨询日期当作争议日期。一般规则咨询不虚构事件日期；具体事件缺关键日期或关系材料时先追问，每轮最多三项。

法条经过版本时间过滤、独立候选检索及适用性检查后进入问答。LLM 仅使用 `[S1]` 等候选编号；法规名称、条号、原文、版本和链接由服务端附加。未知编号、外链、未提供的案号/条号和错误引文不能通过校验。逐字引文若出现在模型正文中，必须匹配所附编号对应版本；默认提示模型不自行抄写原文，由来源卡片完整呈现。各段校验通过后发送，最终异常或保存失败的回答及任务变化不会进入后续上下文。

四领域共享的基础字段为 `event_date/facts/context`，可进一步追问 `relationship_date/discovery_date/end_date`。日期可能仅精确到年/月，过滤采用整个可能区间；不能确认的相对时间会追问。`general_reference` 表示一般规则参考，`event_candidate` 表示事件时间候选依据，两者都不等于已经证明具体案件必然适用。

## 文书

流程：识别类型 → 从消息或结构化参数收集 → 每轮询问 1–3 个缺项 → 展示摘要 → 用户确认 → 固定模板生成草稿。三种模板沿用 M3 字段；`additional_instructions` 可从自然语言中收集为独立补充说明，不自动写成合同义务或诉讼请求。

用户可回复“确认生成”“确认修改”“保留原值”“取消”“重新开始”。新旧字段不一致时保留原值及待确认值，确认修改后重新展示摘要，不直接生成。页面按钮带当前 `task_revision`；过期或陈旧摘要返回 `409 TASK_CHANGED`。已完成文书的重复确认返回已有 ID，不重复生成。另起同领域问题时可使用“重新开始”；取消清空当前任务字段；跨领域新问答不带入旧任务事实。

完成后也可纠正字段，经过冲突处理和再次摘要确认后生成新文书，原文书不覆盖。`POST /documents/generate` 仍是完整结构化参数的显式生成接口，可供调用者在自行审核参数后使用；对话中的草稿必须通过摘要确认。文书不自动添加法律请求或法律依据，已有演示参考仍独立标注，用户提供的事实和说明不会被模型补写。

## 状态、一致性与隐私

最新结构化任务快照嵌入成功助手消息，使用现有 Redis 消息列表和同会话锁，不另建失步的任务缓存。引用的原用户消息即便被 20 条消息裁剪，快照仍保留其原句及 turn UUID。任务与历史共用成功后续期的 24 小时 TTL；过期不从数据库或其他会话重建事实。

用户/助手成对追加和任务快照是同一 Redis Lua 写入；随后提交会话标记及文书事务。失败恢复原快照，提交标记也用于崩溃后的未提交尾部清理。同步和 SSE 共用图节点；在最终保存成功前不发送 `done(success=true)`。全流程仍使用原统一超时预算，不自动重试模型。

状态包含用户事实和原句，因此同样属于咨询内容。服务日志不记录完整提取输入/输出，测试诊断只使用合成信息。生成的文书按所有者保存，不随会话删除。
