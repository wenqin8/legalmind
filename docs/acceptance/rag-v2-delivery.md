## 拦截逐项处理

“剩余4条”指第八轮的MF-04、MF-05、LD-03、CD-02。第九轮4条换为MF-04、LD-01、LD-05、TA-03；两轮去重共7种失败，均纳入 [固定回归样例](../../backend/data/evaluation/offline-v1/validation-cases.json)。

| 场景 | 原失败机制 | 修复与验证 |
| --- | --- | --- |
| MF-04 | 复制了未提供原文的交叉引用编号，修订后仍重复 | 修订反馈列出禁用编号；服务器区分已提供/缺失的交叉引用，缺失部分明确不判断，不能补造条文 |
| MF-05 | 风险段继承前文条件，但审核看不到前文；原回答还扩大了考量因素 | 两次审核都接收已验证前文；校正内容仍严格保留原文因素，不放行扩大条件的原回答 |
| LD-03 | 多段原文被模型拼为一个逐字引文，触发格式拦截 | 只允许服务端片段编号，多段分别指向原文；保留关联用工与共同责任的条件、例外 |
| CD-02 | 原文引用同解释其他条款，删编号被误当删条件；缺失内容被概括 | 显式提供交叉引用状态；本条明示条件可转述，依赖未提供条文的本约判断不补写 |
| LD-01、LD-05 | 适用性/审核阶段复制了非连续支持原文，或未提供被引用条文 | 筛选及审核均选择原文片段；交叉引用按法规名和条号匹配，不能用其他法规同条号替代 |
| TA-03 | 可选意见被写成必要条件，修订引文又拼接失败 | 原文片段合同消除拼接；条件校验保留，错误必要条件仍拒绝 |

7个校正正例和7个原错误负例均通过自动化测试，另覆盖交叉引用名称匹配。校正段落及审核结果为开发者编写的固定测试输入，验证的是处理链和安全边界，不能证明真实模型一定产生这些校正结果。

## 来源不再静默丢失

1. **候选阶段**：保留原查询BM25前三条。以第一条的原文检索相关法规，结合已核验主题词，预留一位给相关的另一法规；再按多样性补齐。仍最多5条，仍须原查询正分，领域/版本/过渡条件先过滤。没有读取金标准、场景ID或答案标签来排序。
2. **筛选阶段**：分别列出直接依据和必要配套依据，两类都须提供原文片段，覆盖所有选中来源。无关或仅泛泛相关的背景材料不要求凑齐。
3. **回答阶段**：模型先在正文说明这些来源的作用。若遗漏，最多一次补充段落；补充内容仍通过编号、逐句支持和独立条件审核，确有受支持的句子才进入最终来源。失败不保存，不退化为直接追加来源卡片。未遗漏时没有额外模型调用，统一总超时不增加。
