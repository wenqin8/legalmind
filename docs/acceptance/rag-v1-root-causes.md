# RAG-v1 质量失败：原因与修复建议

日期：2026-09-20（北京时间）。本次完成代码审查、原始调用轨迹分析和离线复现，未修改生产实现、冻结标签或默认数据库，未重新调用真实模型。机器可读证据见 [离线诊断](rag-v1-diagnosis.json)，脚本为 [diagnose_rag_failures.py](../../backend/scripts/diagnose_rag_failures.py)。

## 1. 门槛到底在哪一层失败

`review_rag_answers.py` 当前只要任一结构硬检查失败，就将 `quality_gate_passed` 设为 `false`；全部无失败则为 `null`，并不会自动给出合格结论。因此，当前还没有一套包含语义审核、故障率和检索目标的完整发布门槛。

现有 `false` 的直接来源是四个日期纠正场景中：旧字段未保留4次、确认后新字段未生效4次。它们是同一类路由缺陷在8个轮次上的表现。不是 Recall@5 低于某个已设阈值导致失败，目前没有这样的数值阈值。

56轮中20轮行为不匹配可分解如下，不能把它们全部解释为法律回答错误：

| 表现 | 轮次 | 说明 |
| --- | ---: | --- |
| 日期纠正、确认修改误入文书 | 8 | 明确实现缺陷，四领域复现 |
| 预期回答却继续追问 | 4 | 排除上述确认轮次后；需区分过度追问与标注缺事实 |
| 预期回答却提示依据不足 | 3 | 护理规则漏召回、交通费和抵销领域识别失败 |
| 返回模型错误 | 1 | 引用校验误拦已离线复现 |
| 预期依据不足却继续追问 | 4 | 未编造结论，但没有准确解释知识缺口；部分预期有歧义 |

另外，较高地区赔偿标准场景通过了现有结构检查，但存在结论没有被所给材料支持的问题。它尚未作为机器硬检查计入当前门槛，不能因修复8次字段失败就宣称法律质量合格。

## 2. 日期纠正丢状态：根因已确认

涉及 `agents/workflow.py` 的 `intent` 节点、`agents/intent.py` 的 `classify_intent` 和 `agents/tasks.py` 的 `advance_task`。

调用链是：上一轮QA任务 → 新消息“更正关键事件发生日期” → 分类模型只接收到当前消息，没有活动任务上下文 → 返回置信度0.9的document → reducer发现任务种类变更，创建空文书任务 → 后续“确认修改”被文书续接规则锁定，持续要求选择模板。

四组保存的模型输出在真实LangGraph节点中均能离线重放出该结果。把同一请求直接交给QA reducer，并提供逐字有出处的日期提取，四组都能保留旧值、进入冲突态并接受新值。说明冲突合并逻辑具备基础能力，首要问题在前置路由；这项对照不代表真实模型提取和完整工作流已修好。

建议：

1. 路由先处理活动任务动作，再识别新任务。`accept_changes/reject_changes/cancel/confirm` 绑定当前任务，先检查revision和阶段；过期或无任务时明确回复，不让分类器猜测。
2. 日期、金额、身份等纠正，以及对当前缺项的补充，默认续接同一task_id。跨任务切换需来自显式新请求或可解释的切换判断，不让单个低上下文分类结果立即覆盖状态。
3. 分类输入包含任务种类、阶段、待补字段等最小上下文。保留显式文书请求、案例搜索、重新开始和新议题的正常入口；不能把所有后续消息都永久锁在QA。
4. 无法确定是补充还是换题时保留原任务并问清意图。QA冲突确认文案不能继续承诺“重新展示文书摘要”。

回归应覆盖四领域纠正、确认/保留原值、文书纠正、明确换题、明确换文书、普通追问、任务过期、过期revision、同步/SSE和失败不落库；故意让假分类器返回错误document，确认状态仍受保护。

## 3. 三个关键漏检：BM25已排第一，被关键词规则删掉

`rag/legal_catalog.py:157` 在BM25排序后要求 `any(keyword in query)`，即预设关键词必须作为完整子串出现在问题中。

隔离内存SQLite导入相同197条资料后，以保存的原始问题重算，结果为：

| 场景 | 应召回资料 | 关键词过滤前名次 | 原实现结果 |
| --- | --- | ---: | --- |
| 社保承诺与补缴 | 劳动争议解释二第19条 | 1 | “社保”不包含“社会保险”等配置词，被删 |
| 护理人数与费用 | 人身损害赔偿解释第8条 | 1 | “护理人数和费用”不包含“护理费”等配置词，被删 |
| 较高地区赔偿标准 | 人身损害赔偿解释第18条 | 1 | 问题未逐字包含配置关键词，被删 |

三条在诊断对照中都能进入无关键词门槛的Top-5；没有扩大K、增加向量库或修改问题。这说明首先需要纠正人为过滤规则，不能把这些失败归咎于BM25本身或资料不存在。三个诊断样本的结果不等于完整测试集的提升幅度。

建议把关键词从硬排除条件降为排序辅助，保留领域、来源和版本边界。在开发集单独比较原规则、去除关键词门槛、带有依据充分性筛选的候选方案；同时看正例Recall、负例误召回和最终错误回答，不能为追求Recall直接把所有有分候选当作可回答证据。需要时再评估语义召回/重排，其依赖、耗时和收益另行衡量，不优先引入新模型。

## 4. 领域为空导致根本没查法条

交通费票据和债权抵销两个场景，`TASK:EXTRACT` 返回domain=null，规则后备也没有命中。`workflow.qa` 只有task.domain非空才进入法条检索，因此两次直接绕过了法条库。提取器同时承担字段提取和领域识别，单个null阻断整条法律检索路径。

对照实验只提供评估标注领域，原检索即可找到对应法条。这个实验定位了上游阻断，不代表已经实现可用的领域识别器。伤者就医也可能源于其他人身损害，不能简单看到医疗费就推断发生交通事故。

建议将检索主题分类与用户事实提取分离；domain=null区分“明确超范围”和“尚不能确定”。对一般规则问题，可在四领域受控语料内检索候选，再核对适用范围；具体事件需影响法律路径时再追问。检索主题标签不能反向写成用户事故类型或身份事实。保留真正超范围负例，不用无限泛化词表消除null。

## 5. 引用真实但结论没有依据：缺少结论级校验

`E-L-TA-16` 的QA输入只有统计口径第22条，输出却先给出可请求较高地区标准的结论。离线重放确认：当前 `validate_citations` 允许此回答通过；它校验编号、外链、可识别原文和案号等，没有检查每项实质结论的支持关系。首段甚至没有引用，只要全文其他位置出现一条允许的编号就能通过。

官方2022年发布文本中，第18条才涉及较高地区标准及赔偿项目限制，第22条说明统计数据和年度口径，二者功能不同。这里是对该发布版本与本次上下文的比对，不是对2026年现行状态或具体案件适用的全面核验。[最高人民法院原始发布](https://www.court.gov.cn/zixun/xiangqing/357071.html)

建议分两层处理：

- 生成前按用户争点检查候选是否包含直接规则，区分直接依据、背景条文、例外及过渡规则；仅有背景条文不能授权主结论。没有直接支持时，只说明能确认的部分和缺口。
- 每段生成后、SSE发送前，检查实质主张对应的来源编号、支持片段及必要条件；支持片段必须与已选版本匹配，再进行独立语义审核。结论没有支持就阻止该段发送，返回受控不足提示或失败，不继续完成为成功答案。不得使用模型自报confidence作为真实性证明。

模型语义审查也会出错，应结合确定性检查、对抗样本和专业人工复核。维持逐段实时发送、统一总超时、取消和失败不入历史；新检查消耗总预算，不做无限重试，也不靠全文生成后才检查来绕过现有SSE要求。已经发出的段落无法撤回，因此跨段条件缺失也要纳入检查设计。

检索质量、来源忠实性和回答质量应分开评估，这与[Ragas原论文](https://arxiv.org/abs/2309.15217)区分多个评价维度的思路一致；这里只采用评价思路，不新增Ragas依赖，也不以自动评分替代法律审核。

## 6. MODEL_UNAVAILABLE：本地误拦已复现

`E-L-LD-01` 保存的第一段含“这些材料并未直接规定”后接概念性引号。`agents/evidence.py` 的正则只要引号前近邻包含“规定”等词，就将它视为法条原文；未附紧邻引用编号时source为None，直接抛出ModelUnavailableError，忽略了这里是在否定材料已规定该内容。

使用保存的字节内容、每7字符分块调用真实 `generate_qa`，无需网络即可得到MODEL_UNAVAILABLE，第一段尚未发出，流被关闭。仅移除概念引号，同一段通过引用检查。因此这是可确认的本地校验触发路径，不能把该记录算作已经证实的模型服务宕机。原调用记录的GeneratorExit与本地关闭相符；完整回答被取消，无法判断其余未生成内容。

建议对真正原文引用使用显式结构和source_id；普通术语引号、否定/缺失说明与法条引文分开识别。不能简单移除所有引号检查，伪造原文仍须被拒绝。补充最小差异测试：概念引号、否定“未规定”、显式“原文”、无编号原文、错版本、跨段引号和分块编号。

错误观测也应区分provider失败、超时、输出截断、引用格式、原文不符和证据不支持。可以先保留外部错误合同，增加不含用户正文/密钥的内部reason_code和阶段；若改变对外错误码，应同步API合同与客户端处理，不能把校验失败伪装为成功。

## 7. 过度追问、无资料与模型失败被混为一谈

当前 `QA_REQUIRED` 对具体事件固定要求event_date/facts/context，适用性模型还可返回任意允许字段；服务端只检验字段在白名单和问题格式，没有核验该缺项是否真的阻断本次争点。`legal_evidence` 对无候选、无法适用、非法模型输出和超时都可能返回相同的空结果，随后回退到演示资料。信息缺失原因已经丢失。

例如营养费场景补日期后，模型要求discovery_date，但本次只问一般证明方向，并未要求时效结论。相反，关系持续时间跨版本时继续追问可能必要，不能一概关闭追问。

建议返回有类型的证据决策，至少区分可支持、缺必要事实、知识未覆盖、版本不能确认、依赖失败。缺项必须关联具体争点及会改变哪个判断；已有值不重复索取，非阻断字段放入下一步建议。地方标准、历史版本或具体金额依据缺失时直说缺哪些资料，不能暗示用户再补普通事实就能从现有库得出答案。

演示来源和官方依据分别使用回答策略：仅演示时不生成具体规范结论；有官方依据时不套用“只有演示资料”的句子；模型认为无关的演示材料不应为了满足“至少一条引用”而保留。提示词约束需要用输出检查和负例验证，不能假定改提示词即已修复。

## 8. 实施顺序和验收方式

1. **P0：状态与可观测性。** 先给路由丢状态、引号误拦补失败回归，再修复；记录分阶段原因，避免后续检索调整掩盖故障。
2. **P0：证据约束。** 与召回修复配套增加直接依据充分性、结论支持检查；冻结“背景条文被冒作直接依据”等反例。否则召回提升也不能证明回答可靠。
3. **P1：检索与领域入口。** 先比较去除硬关键词门槛，再改domain=null退路；每次只改变一层，保持相同问题、语料和版本。负例安全性必须一起报告。
4. **P1：补事实策略。** 按问题目的和阻断条件追问，区分资料缺口；补规则介绍/个案适用、地方资料缺失和跨版本关系的回归样本。
5. **P1：完整验收门槛。** 把结构、任务状态、语义支持、拒答/追问、依赖故障和服务性能分列。先冻结数值目标及分母，再运行新评估。任何已知无依据实质结论、跨用户访问、未确认覆盖关键字段或失败回答进历史，均应阻止发布；样本零失败不是总体零风险。

原v1数据、标签和分数不回写。标注有歧义的题进入独立复核记录，明确所问争点、必要事实和允许行为，可在v2接受有理由的条件回答/追问；不能因实现做不到就把错误响应改成正确标签。现有保留集已看过，只用于回归，另建未见验收集，并明确标注者、复核者和语料核验边界。不要把197条隔离库成绩套到仍只有60条的默认服务。
