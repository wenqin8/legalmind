# MF04 的424原因与离线修复

2026-10-01。本轮真实模型调用0；修复代码已进入本机Docker后端。程序回归通过，新提示词的真实生成效果尚未测量，最终法律验收仍未通过。

## 原因

问题询问夫妻一方将共同财产赠与婚外同居对象后，另一方要求返还的一般规则。[原始Run11](m4-real-development-20261001-run11.json)的MF04首轮返回424；[诊断记录](m4-mf04-rag-diagnosis-20261001.json)绑定其SHA-256和本次实现。

1. 主依据已经命中。五候选包括婚姻家庭编解释（二）第七条及民法典第1062条，不能归为完全漏检。第1063条的个人财产例外在库里但未进入候选；第157、1066、1092条全文则不在209条核验库里，属于资料覆盖缺口，不能用提高Top-K或提示词补出。
2. 适用性筛选将第七条第一款标为直接片段，又将第二款财产分割请求标为配套片段；旧程序合并后只留下来源级direct角色。生成模型扩展了用户未问的独立请求，并把共同财产范围概括为相关财产。
3. 一次修订补充范围和前款条件后，末次审核以未重复第1066、1092条编号为由拒绝；首轮还称候选缺少前款前提，但候选已有前款情形且前文提供了其内容。这些解释存在误拒风险，不能据此断定答案实体法律错误。
4. 旧引用规范化把多个缺失的被引用条文替换成同一泛称，丢失引用之间的身份；只有provided/not_provided状态相同，也不能认作同一引用。

已核对[最高法解释原文](https://www.court.gov.cn/zixun/xiangqing/452771.html)第七条两款及[官方民法典正文](https://www.cac.gov.cn/2020-06/01/c_15925617772683194.htm)第1062、1063、1066、1092条。该核对用于判断程序是否混淆条号与条件，不替代独立法律专家验收；网页内容没有自动导入冻结语料。

## 改动

| 层次 | 当前行为 |
| --- | --- |
| 检索 | 第五个候选槽位可补入完整原文明确引用、已有核验记录的条文；先按领域、状态和日期过滤，保留前四个原候选和已命中的明确配套目标，最多五条、不递归扩展。缺失或身份不唯一的目标保持缺口。 |
| 适用性 | 同条直接片段与仅作配套的片段分别保留。直接、配套重叠时仍以直接为准；提示只选用户请求所需的分支。 |
| 生成与修订 | selected_spans保留answer/context用途，完整原文用于条件核对。配套上下文不能新增独立请求；未问的失败分支在一次修订中收窄为本次不展开。 |
| 双层审核 | 同样获得selection_scope，继续比较完整原文，检查实际请求及完整前提。拒绝时须指明实质条件，不能仅要求复写条号，也不能猜测缺失条文一定有额外条件。 |
| 引用身份 | 原文确认的交叉引用使用不同配套标识；同一目标的重复引用保持一个身份。同状态但不同法条的裸编号歧义仍不替换，未知编号仍拒绝；缺失全文不变成新来源。 |
| 明确错误保护 | 真实记录中的共同财产笼统概括在调用模型审核前被确定性拒绝，补充否定句和免责声明反例，避免错拒正常否定或用免责掩盖错误。 |

每段仍仅允许一次修订，随后完整重审；失败内容不作为成功答案保存。HTTP424/MODEL_UNAVAILABLE的既有对外合同本轮保持，语义拒绝与供应商故障的显示分类仍可另行优化。
