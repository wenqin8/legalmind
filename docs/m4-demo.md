4. 展示独立会话、删除、退出登录以及跨用户拒绝访问的证据。文书不随会话删除；历史是24小时滑动TTL，过期须重新补充事实。
5. 展示[实际部署浏览器Run15](acceptance/m4-deployed-browser-20261001-run15.json)的4/4及[重启后运行Run8](acceptance/m4-deployment-runtime-20261001-run8.json)的9/9：账户、Redis历史、文书与索引保留。移动导航320/390/640px已检查。
6. 执行下方隔离浏览器命令，说明正常咨询与故障场景使用测试模型、测试会话存储及隔离数据库，零付费调用；不是当前真实模型质量证明。

## 五类可重复场景

| 场景 | 可见行为 | 当前证据 |
| --- | --- | --- |
| 正常 | 注册、增量回答、来源、刷新恢复及追问 | 隔离Run8的normal项，测试模型与存储 |
| 空结果 | 无结果提示，无编造案例 | 隔离Run8的empty results项 |
| 超时 | 标记未完成、提供安全重试、无成功来源 | 隔离Run8的timeout项 |
| 断流 | 停止后未完成，失败片段不提交为成功历史 | 隔离Run8的disconnect项 |
| 非法令牌 | 清理登录态，跳转登录 | 隔离Run8的invalid token项 |

在frontend目录运行，使用已经安装的Edge及新的报告路径：

```powershell
$env:LEGALMIND_E2E_BROWSER_CHANNEL='msedge'
$env:LEGALMIND_E2E_OUTPUT=Join-Path (Resolve-Path ..).Path 'tmp\course-demo-new.json'
npm.cmd run test:e2e
```

自动化打开无界面浏览器，运行9组断言后退出并保存报告；它占用8011和5173端口，拒绝接管已有服务。若已有日常开发服务监听，请先按日常方式停止该服务。本次[Run8](acceptance/m4-browser-e2e-20261001-run8.json)9/9通过；首次[Run7](acceptance/m4-browser-e2e-20261001-run7.json)因缺少Playwright Chromium失败，改用本机Edge后通过。
